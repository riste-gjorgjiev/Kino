- Scope: global styles, typography, spacing, buttons, cards, nav polish, mobile layout
- Acceptance criteria:

  - Cards, buttons, inputs use consistent design tokens.
2) UX States & Feedback (1–2 days)
- Scope: skeleton loaders, empty states, error handling UX
- Acceptance criteria:
  - Home, list, search, details show skeletons while loading.
  - Empty states are meaningful (no blank screen) and consistent across pages.
  - Errors show user-friendly messages with retry where applicable.
3) Discovery Features (3–5 days)
- Scope: sorting + filtering, additional home carousels
- Acceptance criteria:
  - List pages support sort (popularity/rating/date/title) and at least 1–2 filters (genre/date range).
  - API accepts query params; frontend wires UI to backend.
  - Home page shows multiple carousels (e.g., Trending, Popular, Top Rated, Upcoming).
4) Details Enrichment (2–4 days)
- Scope: trailers, keywords, recommendations
- Acceptance criteria:
  - Details page shows trailer link (TMDB videos) when available.
  - Keywords section is visible for movie and TV where applicable.
  - “More like this” section works for both media types.
5) TV Seasons & Episodes (4–6 days)
- Scope: seasons/episodes data, UI for episodes
- Acceptance criteria:
  - Season selector loads episodes and displays runtime/air date.
  - Handles shows with multiple seasons gracefully (pagination or lazy load).
6) Backend Reliability & Performance (2–4 days)
- Scope: caching strategy, rate-limit handling, API resilience
- Acceptance criteria:
  - Caffeine caches details/search with reasonable TTLs.
  - TMDB errors surface as consistent API errors.
  - Basic retry/backoff for transient TMDB errors.
7) Auth & User Features (long-term, 2–4 weeks)
- Scope: users, watchlist, ratings/reviews
- Acceptance criteria:
  - Auth flow (register/login) and protected routes.
  - Watchlist + favorites persisted in DB.
  - Ratings/reviews per user per media item.
